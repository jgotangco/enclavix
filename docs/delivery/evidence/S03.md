## Delivered increment
- Private additive migration adds association setup, operator lifecycle audit/idempotency, registry exports and offboarding staging (26 current app tables), plus canonical code indexes and stable contact keys.
- Named commands implement village/condo structures, properties, contacts, assets, updates, effective relationships/primary/billing contacts and transfers. Self-entitlement changes, auth/role payloads and cross-scope references are rejected. Representative access now depends on the represented owner's current relationship.
- D13 creation/submission/review binds activation to a current revision, recomputes its checklist, requires a different operator and constrains every setup to sandbox mode. Revoked nominees lose setup and registry access.
- Shared cookie/native routes under `/api/v1/community/*` expose strict commands, bounded requests, durable retry keys and no-store responses. `/workspace` supplies sequential setup/registry forms, visible association/community/property selection, row reconciliation, export downloads and offboarding staging. Old mock portals remain isolated.
- Imports support property/person/asset/relationship rows only: preview, logical row errors, totals, canonical parsed-content fingerprint, explicit confirmation, atomic revalidation/commit and cancellation. Conflicting repeated relationship intervals must be split into separate batches. Exports exclude auth bindings, file contents and finance; staging never terminates access or deletes data.
- Contracts: ADR 0006 and docs/community-api.md. README, development/security guides, traceability and decisions reflect this increment.
